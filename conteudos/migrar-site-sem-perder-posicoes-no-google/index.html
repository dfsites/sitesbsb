Como trocar de site ou hospedagem sem perder posições no Google

Como planejar a troca de site, domínio ou hospedagem com mapeamento de URLs, redirecionamentos 301, sitemap e Search Console para preservar o tráfego.

Por Equipe Sites Brasília

Trocar o site por um novo é, muitas vezes, a decisão certa. O problema é que muitas empresas fazem a troca, comemoram o visual novo e, semanas depois, percebem que os contatos vindos do Google caíram. Na maior parte dos casos, a causa não é o site novo em si, mas a forma como a mudança foi feita.

A boa notícia: uma migração bem planejada reduz muito esse risco.

Por que um site perde posições na migração

O Google conhece o seu site pelas URLs, os endereços de cada página. Ao longo do tempo, essas URLs acumulam histórico: links de outros sites, cliques, relevância para determinadas buscas.

Quando o site novo muda os endereços sem avisar o Google, acontece o seguinte:

  • as páginas antigas passam a mostrar erro de página inexistente (404);
  • os links que apontavam para elas deixam de ajudar;
  • o Google precisa redescobrir tudo do zero.

Outros problemas comuns: textos importantes removidos, títulos alterados sem critério, páginas bloqueadas por engano e site novo bem mais lento.

Tipos de migração

Tipo de mudança Risco para o SEO Principal cuidado
Só troca de hospedagem, mesmo site e mesmas URLs Baixo DNS, SSL e tempo de resposta
Site novo, mesmo domínio, URLs diferentes Médio a alto Mapeamento e redirecionamentos 301
Troca de domínio Alto Redirecionar tudo e avisar o Google
Mudança de HTTP para HTTPS ou de “www” para sem “www” Médio Redirecionamento completo e consistente

Se a mudança for só de hospedagem, o foco é não derrubar o site nem o e-mail durante a troca de DNS. Se envolve site novo ou domínio novo, o trabalho de SEO é bem maior.

Passo 1: levante o que existe hoje

Antes de mexer em qualquer coisa, faça um inventário do site atual:

  • Lista de todas as URLs: pelo sitemap atual, por uma ferramenta de rastreamento ou pelo próprio Search Console.
  • Páginas que trazem mais visitas e contatos, pelo Google Analytics ou ferramenta equivalente.
  • Buscas que geram cliques, no relatório de desempenho do Google Search Console.
  • Páginas com links externos, que recebem links de outros sites.
  • Títulos e descrições das páginas principais.

Guarde esses dados. Eles servem para planejar e, depois, para comparar.

Passo 2: mapeie as URLs antigas para as novas

Monte uma planilha com duas colunas: URL antiga e URL nova. Cada página antiga relevante deve ter um destino equivalente no site novo.

Regras práticas:

  • Redirecione para a página mais equivalente em conteúdo, não para a página inicial.
  • Se uma página antiga não tem equivalente, avalie se vale criá-la no site novo, principalmente se trazia visitas.
  • Páginas realmente sem valor podem ficar sem redirecionamento, mas decida isso com os dados, não no chute.
  • Evite cadeias de redirecionamento (A leva para B, que leva para C). O ideal é um salto direto.

Passo 3: configure redirecionamentos 301

O redirecionamento 301 diz ao navegador e ao Google: “esta página mudou de endereço de forma permanente”. O visitante que chega pela URL antiga é levado automaticamente para a nova, e o Google entende que deve transferir a relevância.

Cuidados:

  • Use 301 (permanente), não 302 (temporário), para mudanças definitivas.
  • Teste cada redirecionamento antes e depois de publicar.
  • Mantenha os redirecionamentos por muito tempo. Remover cedo demais desfaz o trabalho.

Passo 4: preserve o que funcionava

Um site novo não precisa copiar o antigo, mas não deve jogar fora o que funcionava:

  • mantenha textos relevantes das páginas que traziam tráfego, melhorando em vez de apagar;
  • preserve títulos e termos importantes das páginas bem posicionadas;
  • mantenha a estrutura de páginas por serviço, se ela existia;
  • não esqueça páginas como blog e perguntas frequentes, que costumam trazer visitas.

Passo 5: cuide da parte técnica antes de publicar

  • Confirme que o site novo não está bloqueado para mecanismos de busca. É comum o site em desenvolvimento ter uma instrução de “não indexar” que vai para o ar por esquecimento.
  • Garanta que o SSL está ativo e que todas as versões do endereço levam para uma só.
  • Verifique a velocidade e a versão para celular. Veja meu site está lento.
  • Gere um sitemap novo, com as URLs novas.

Passo 6: publique e avise o Google

No dia da publicação:

  1. Teste uma amostra das URLs antigas e confirme que redirecionam corretamente.
  2. Envie o sitemap novo no Google Search Console.
  3. Se houve troca de domínio, use a ferramenta de mudança de endereço do Search Console, com os dois domínios verificados.
  4. Confira se a página inicial e as principais páginas estão acessíveis e indexáveis.

Passo 7: acompanhe nas semanas seguintes

Oscilações logo depois da migração são comuns enquanto o Google processa as mudanças. Acompanhe:

  • Erros 404 no Search Console e corrija os redirecionamentos que faltaram;
  • páginas indexadas, para ver se as novas estão entrando;
  • cliques e impressões comparados com o período anterior;
  • contatos gerados pelo site, que é o que importa no fim.

Se a queda persistir, compare as páginas que perderam tráfego com as antigas: geralmente falta um redirecionamento ou algum conteúdo foi removido.

Erros mais comuns

  • Redirecionar todas as páginas antigas para a página inicial.
  • Publicar o site novo com bloqueio de indexação.
  • Trocar o DNS sem copiar os registros de e-mail.
  • Apagar o blog antigo por achar que “ninguém lê”.
  • Remover os redirecionamentos pouco tempo depois.
